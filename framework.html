Swimlane Workflow View (Admin | Inspector | Valuer | Council | Owner)

This view shows the end-to-end operational workflow and quality-control loop: Admin assigns → Inspector captures & submits → Admin QA approves/rejects → Valuer values → Council publishes → Owner views & objects.

Admin

Coordinator
1. Create Assignment Select property type, set required attributes template, assign to inspector.
2. Maintain Comparables Enter verified sale/rent records used in Sales Comparison method.
3. Quality Check (QA Gate) Review submissions → Approve (ready for valuation) or Reject (send back).

Inspector

Field Data
4. Collect Property Data Capture attributes, GPS coordinates, photos/documents (offline-first).
5. Submit to Admin Send completed assignment for QA review.
Rework if Rejected Receive feedback → correct data → resubmit.

Valuer

Professional
6. Review Approved Records Work only on Admin-approved property data to ensure quality input.
7. Run Valuation Apply Sales Comparison / Income / Cost fallback based on rules & data.
8. Finalize & Record Store valuation results, method used, and notes in the system.

Council

Oversight
9. Generate Valuation Roll Compile valuations into official roll; export reports for administration.
10. Publish & Notify Publish roll and communicate outcomes via system notifications.
11. Manage Objections Review objections; assign reassessment when necessary; update roll.

Owner

Transparency
12. View Valuation See value, method used, and valuation history (where enabled).
13. Submit Objection Submit claim with evidence (wrong attributes, clerical errors, etc.).
14. Track Outcome Follow objection decision and updated valuation status.
Key Loop: If Admin QA rejects a submission, it returns to the Inspector for correction and resubmission.

INPUT MODULE Data Capture & Assignment

Collect → Verify → Prepare property data

Data accuracy is critical (“garbage in, garbage out”). Offline capture and templates enforce required attributes.

Admin Dashboard — Assignment Creation

Coordinator
  • Create field assignments by property type (residential / commercial / industrial / special use).
  • Define data templates (questionnaires) for required attributes.
  • Include GPS/location and owner information.
  • Maintain comparable database (verified sale & rental records + evidence).
  • Review inspector submissions: approve or reject with feedback.
✅ Output of Admin: Approved property records + verified comparables ready for valuation.

Inspector Dashboard — Mobile App (Offline)

Field Data
  • Open assignments, fill pre-configured questionnaires by property type.
  • Capture GPS coordinates + attach photos/documents.
  • Works offline; syncs automatically when internet is available.
  • If rejected: receives feedback → correct → resubmit.
📶 Offline-first: designed for low-connectivity areas; sync later when online.
Standards enforced in Input Module
  • Measurement standards: IPMS / RICS (consistent floor area: GIA, NIA).
  • GPS precision: target accuracy below 10 meters.
  • Evidence integrity: photos with EXIF timestamp & geolocation.
  • Mandatory attributes: templates enforce required fields before submission.
Input validation & approval gate

All captured data passes a gate: Admin checks accuracy and completeness. If rejected, inspectors receive feedback for correction and resubmission. This prevents bad data from entering valuation.

PROCESSING MODULE Valuation & Analysis

Valuation engine + Professional review + QA

Engine applies the right method per property type and data availability; valuers can override with justification.

Valuer Dashboard

Professional Control
  • Receive assignments containing pre-approved property data.
  • Run valuations individually or in batch mode.
  • Override automated results with justification + evidence.
  • Flag incomplete/non-standard records for correction.
🧑‍⚖️ Hybrid approach: combines professional judgment + digital automation.

Valuation Engine

Automation
Method selection rules
  • Residential: Sales Comparison Method (using verified comparables).
  • Commercial: Income Approach.
  • Default: Cost Method when comparable data is insufficient.
Comparable selection algorithm
  • Select at least 3 comparables in same area + time window.
  • Compare attributes (size, age, condition, location).
  • Apply weighted adjustments (e.g., regression).
  • If fewer comparables: expand search radius or time range.
Quality assurance
  • Detect outliers (residual analysis).
  • Compute error metrics (e.g., RMSE).
  • Assign confidence scores to each valuation for reliability.

Council Dashboard (Processing-side oversight)

Oversight
  • Review valuations and generate official valuation rolls.
  • Export valuation roll and reports.
  • Monitor objections and ensure transparency/publication compliance.
🏛️ Council ensures valuation roll generation & compliance with publication requirements.
OUTPUT MODULE Publication & Owner Interaction

Publish → Notify → Objections & Appeals

Owners see their valuation details and can submit objections digitally with evidence; audit trail ensures accountability.

Property Owner Dashboard

Transparency
  • Secure login to view valuation details (method used, final value).
  • View GPS-linked records and valuation history.
  • Download available statements/reports.
  • Audit trail records every update (accountability).
📣 Publication + notifications improve transparency and public trust.
Objection & appeal mechanism
  • Owners submit objections digitally with evidence.
  • Council/Admin reviews validity; may assign a valuer for reassessment.
  • Decisions recorded; valuation roll updated accordingly.
Output deliverables
  • Published valuation roll (council-controlled).
  • Owner-facing statements & valuation summaries.
  • Objection log with decisions + roll updates.
  • Audit logs for every modification (who/what/when).
